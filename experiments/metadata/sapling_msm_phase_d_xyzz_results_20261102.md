## 3. 正确性（C1–C8，16 项全通过）

`experiments/prover-smoke/src/bin/msm_xyzz_gate.rs`，`16 PASS, 0 FAIL`：

- C1 identity+P、C2 P+Q、C3 P−Q、C4 P+P==double、C5 P+(−P)==identity、

- C7 1024 个随机仿射点连续加减累加；C7b 512 桶 / 4096 次填充的桶归并；
  C7c XYZZ+XYZZ 的三种退化（同点、互逆、identity）；
- C8 **完整 MSM 等价**：n = 8 / 1024 / 131,071 三个规模，
  Jacobian 与 XYZZ 路径输出经非压缩序列化后**逐字节相等**，且各自重复调用确定。

所有比较都是曲线群元素的字节比较，不以「程序未报错」代替正确性。

## 4. 归因：为什么 XYZZ 反而更慢

预注册的假设是「bucket fill 的混合点加公式是差距所在」。实测把这个假设切成了
两半，结论是：**公式本身持平，把它拖慢的是「必须判断退化情形」这件事。**

### 4.1 三层分解（各层独立测量，不可直接相加）

`experiments/prover-smoke/src/bin/msm_xyzz_attrib.rs`，同一 fill 模式
（4,096 桶、随机下标、131,071 次混合加），跑 3 次：

| 臂 | run 1 | run 2 | run 3 | 相对 Jacobian |
|---|---|---|---|---|
| jacobian | 119.584 ms | 119.313 ms | 118.739 ms | — |
| xyzz（含退化检查） | 122.821 ms | 123.778 ms | 125.670 ms | **+2.7% ~ +5.8%** |
| xyzz（unchecked，仅公式） | 118.972 ms | 120.124 ms | 118.996 ms | **−0.5% ~ +0.7%（持平）** |
| 退化检查代价 | 27.9 ns/add | 50.9 ns/add | 49.3 ns/add | **+3.1% ~ +5.6%** |

三次重复中 `unchecked` 始终落在 ±0.7% 内，`checked` 始终为正 —— 方向稳定。

| 层 | 结果 |
|---|---|
| ① 公式本身（unchecked） | **≈ 0**（−0.5% ~ +0.7%，在噪声内持平） |
| ② 退化检查（checked − unchecked） | **+3.1% ~ +5.6%** |
| ③ 完整 MSM 的其余部分 | 总计 `1/0.9368 − 1 = +6.75%`，扣除 ② 后约 **+1.5 ~ +3.5 个百分点** |

③ 的构成：桶初始化（4,096 × 192 B vs 144 B）、桶归并（XYZZ+XYZZ 12M+2S vs
Jacobian 全加）、20 个窗口各一次 `into_projective`（1 次求逆）、以及更大的桶数组
带来的缓存占用。

### 4.2 为什么会这样

| 项 | 现有 Jacobian（eprint 2015/1060, Algorithm 8） | XYZZ（`madd-2007-bl`） |
|---|---|---|
| 乘法 | 11 M | 9 M + 2 S |
| 「乘 3b」 | 2 次 `mul_by_3b` = 6 次 Fp 加法（几乎免费） | 无 |
| Fp 加法 | 19 | 13 |
| 常驻坐标 | 3 个 Fp（144 B） | 4 个 Fp（192 B） |
| 每次加法的退化判断 | 1 次 `rhs.is_identity()` | **3 次**（self identity、H==0、r==0） |

三点合起来解释了「公式持平」：

1. **`Fp::square` 只比 `mul` 便宜 17%**（同构 `Scalar` 实测 square/mul = 0.834，
   `Fp` 类型私有、无法直接测，用同宽度 Montgomery 实现作量级参考，见偏离 D5）。
   所以 XYZZ 省的 2 个平方 ≈ 0.33 个乘法。
2. **Algorithm 8 已经用 `mul_by_3b` 把两个乘法项换成了纯加法**，11 M 里没有水分。
   于是两边的「乘法当量」是 11 vs 10.67 —— **本来就没有多少空间**。
3. **多出的 2 次退化判断是硬成本**：`Fp::is_zero()` 是常数时间比较（6 个 limb 的
   `ct_eq` 加归约检查），每次约 25–50 ns；XYZZ 需要判断三次，Jacobian 只需判断
   `rhs` 是否无穷远一次。2.6 M 次加法上累积就是数十毫秒。

**关键点**：那两个判断不能省。`add_mixed_assign_unchecked` 之所以快，正是因为它
在退化输入上会给出**错误结果**（identity 桶、P+P、P−P 全部算错）。所以
「unchecked 的 +0.7%」不是一条可用的优化路线，而是一个测量上限：
**XYZZ 在这套 Fp 实现上最多只能追平，不可能领先。**

### 4.3 对 Phase C 结论的修正性解释

Phase C 测到 Bellman/blst = 1.90×，并把差距归因到「bucket fill 的点加公式」。
本次实验给出更准确的表述：

> **差距在 Fp 乘法核（实现与调度），不在桶坐标的选择。**

理由：把桶换成 XYZZ、公式换成 9M+2S 之后，单次混合加仍然是 910–940 ns；
而每次加法要做 11 个 Fp 乘法，即 **~83 ns/mul**（按 910 ns ÷ 11 计）。
blst 反推的 253 ns/add 若同样是 11 个乘法，则每次约 23 ns —— 差距几乎全部在这
一项上。坐标表示改变不了每个 Fp 乘法花多久，只有乘法核（ADX/MULX、
AVX-512 IFMA、延迟更低的 Montgomery 归约、更好的寄存器调度）能改变。

这是一个**可检验的负结论**：若未来要把差距收回，正确的着力点是 Fp 乘法实现，
不是坐标系统，也不是窗口参数。

## 9. 这条负结论的价值

1. **排除了一条看起来最自然的路线**。阶段 C 的归因指向「点加公式」，
   本次证明在本实现下换坐标最多持平、实际净亏，因此不该再做坐标层面的尝试。
2. **把注意力指向真正的瓶颈**：Fp 乘法核。这是下一步唯一有量级空间的方向。
3. **保留了可复现的否证链**：正确性 16 项、A/A 漂移 0.03%、CI 宽 0.003、
   三层归因独立测量。任何人可以用同一条命令重跑并得到同样结论。

按研究纪律，这比为凑出一个「快了 3%」的脆弱结论更有价值。
