## 5. 新发现：无参派生的 index 游标不受快照恢复约束

这是本轮**唯一一处推翻既有判断**的发现，必须单独记录。

### 5.1 观测

| 时刻 | 动作 | 无参派生得到的 index | addresses |
|---|---|---|---|
| 11:33 | 恢复 #1 后立即派生 | 4610657118 | 38 → 39 |
| 11:33 | 恢复 #2 后立即派生 | 4610657129 | 38 → 39 |
| 11:34 | 恢复 A 后连续 3 次派生 | 4610657193 / 4610657195 / 4610657197 | 38 → 41 |
| 11:34 | 恢复 B 后派生 1 次 | 4610657204（**高于** A 的最后一次） | 38 → 39 |

两次相同恢复的 `addresses` 均回到 **38**、`listaddresses` 最大 index 均回到 **4610582439**（与归档一致，
两者一致=True），说明**恢复本身是忠实的**；但无参派生得到的 index 逐次抬升，且**不回到 4610582440**。

### 5.2 否定性证据（排除的可能解释）

| 假设 | 检验 | 结果 |
|---|---|---|
| 外部状态文件 | `find ~/z3-regtest -newermt "-15 minutes"`，过滤 log/.bak/bin | 只有 zebra-state 与 `wallet.db`、`.lock`，**无额外文件** |
| 独立状态目录 | `~/.local/share`、`~/.config`、`~/.cache`、`~/.local/state` 搜 zallet/zcash | 无命中 |
| DB 内的游标列 | 遍历所有表，找 `index/cursor/next` 语义列 | `addresses` 只有 `diversifier_index_be`，**无 next-cursor** |
| `listaddresses` 枚举口径不同 | 对比 DB `max(hex)` 与 `listaddresses` 最大值 | 两次恢复后均相等（4610582439） |
| 恢复未真正解包 | 两次恢复后 `addresses` 均为 38；日志各有 1 次"已还原" | 恢复确实生效 |

### 5.3 结论与定性

- **事实**：`z_getaddressforaccount(0, ["sapling"])`（无参、不带 index）使用的 index 是**跨进程、跨恢复单调递增**的，
  当前值比归档 `addresses` 最大 index 高约 74.7k。机制**未定位**（wallet.db 内无对应列，外部无状态文件），
  因此本文只把它记为**观测事实**，不给出机制结论。
- **影响面**：`sapling_ua()`（sender）用的就是无参派生；它先于收款地址派生，而起点取
  `max(listaddresses)+1`，所以**每轮起点不同**（实测 4610656953 → 4610657067 单调上升）。
- **不是本次补丁引入的**：前次真实门禁 7 次成功用的也是每次不同的 sender 地址，行为与补丁前一致。
- **对测量无影响**：index 值不参与交易构造、不参与计时；每轮实际 index 已落入 `rounds.csv`，可逐轮追溯。
- **对"冻结基线"的含义**：快照并未覆盖钱包的全部可变状态，存在至少一处不受恢复约束的派生游标。
  这一点应写进正式报告的限制说明，不能声称"每次恢复后环境完全一致"。

### 5.4 待你决定（未擅自改动）

若希望每轮 index 完全可复现，可把 D2 的起点从 `max(listaddresses)+1` 改为**固定基数**
（如 10^15，每轮恢复后都从同一处开始）。代价是偏离你已批准的 D2，且地址不再"紧接 sender"。
**当前实现按你批准的 D2 保留，未改。**

## 7. 实施中的两处与设计稿的偏差（如实记录）

1. **地址准备被放在 `wait_sync()` 之前**。设计稿 §4 写的是 `wait_sync → prepare → build_amounts`；
   实际把 `prepare_recipients` 放在原 `recipients = ...` 的位置（即 `wait_sync` 之前）。
   理由：`listaddresses` 不依赖链同步，失败可以早停，避免白等 10–12s 的追平。
   语义上仍然满足"地址准备在交易构造之前"这条硬约束。
2. **预算估算被实测修正**：设计稿估"n_recip=8 期望约 12 次"，实测 17（独立验证）/ 19（dry-run 第 7 轮）。
   预算 64 未变，余量约 3.4 倍。
