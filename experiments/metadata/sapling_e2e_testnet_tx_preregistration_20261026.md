# 预注册：端到端 Testnet 真实 Sapling 转账——耗时与内存剖析 — 2026-10-26

> 本预注册冻结端到端实验的测量方案与判定门槛，遵循仓库 `experiments/metadata/*_preregistration_*.md` 惯例。
> 阈值与统计方案在看到结果前冻结，不得事后修改。
> 配套范围界定：[`sapling_real_input_tx_proving_scoping_note_20261026.md`](sapling_real_input_tx_proving_scoping_note_20261026.md)。

---

## 1. 目标与待测量（非预期收益）

- **主要目标**：在 Testnet 上完成真实 Sapling 转账，量化从输入准备到交易确认的**全过程耗时与内存**，并分离**证明生成**成本。
- **待测量（冻结）**：
  - 各阶段耗时：钱包 / 输入准备、交易构造、Spend proving、Output proving、序列化、本地验证、广播→节点接受、等待首次确认、钱包最终识别。
  - 各进程内存峰值：钱包进程、节点进程、二者同时运行总占用（峰值工作集 + 私有内存）；首次同步峰值与证明生成期间峰值独立保留；记录 Zallet 历史扫描 batch size。
  - 最终交易大小、各份证明大小。
- **明确不是目标**：证明器优化、确认 NU6.3 以外的新特性、跨主网资金。本阶段是测量与剖析。

## 2. 技术路线（冻结）

- 节点：**Zebra**（Testnet 网络）；钱包：**Zallet**（Beta，Testnet）。
- 分阶段 RPC：`pczt_create` / `pczt_prove` / `pczt_sign` / `pczt_extract`。
- **功能验证优先在 Testnet**；不依赖 Regtest 作为完整花费环境（Zallet Beta 已知限制）。
- 对照基线：既有本地 `Builder::build` 链路分段（合成 Merkle 状态，2026-10-22）保留为比较基准。

## 3. 测试负载（冻结）

- 单笔交易形态：沿用既有实验的 **1 spend + 2 outputs**（1 找零 + 1 收款）作为主负载；
  可扩展至多输入以观察 witness 准备成本随输入数变化（扩展为可选，不纳入主判定）。
- 重复样本：功能验证 1 笔；正式测量 **N ≥ 5 笔不同可花费 Note**（具体 N 在功能验证后按 Testnet faucet 可得性冻结）。

## 4. 功能验证门禁（先于重复测量）

- [ ] Zebra Testnet 同步成功，Zallet 能识别并花费一笔 faucet 到账的 Note。
- [ ] `pczt_create → pczt_prove → pczt_sign → pczt_extract` 全流程跑通，提取的交易能被节点接受并最终进入区块。
- [ ] 至少一笔交易达到 N 确认，钱包能识别收款。
- 任一门禁失败 → 暂停并回报环境 / 工具限制，不进入重复测量。

## 5. 正确性 / 功能确认

- 每笔交易：节点接受、落入区块、达到 N 确认；收款方钱包识别并解码 note。
- 交易结构常量、证明与签名在本地可被既有验证路径复验（如可行）。

## 6. 统计方案（冻结）

- 正式测量每阶段取多笔中位数与波动范围（min / median / max 或 IQR）。
- **确认相关阶段（广播→接受、等待确认）与本地证明阶段分表报告**，不合并为单一「总耗时」。
- 若 `pczt_prove` 仅暴露总证明时间而无法分离 Spend / Output，则：
  - 主报告记录 `pczt_prove` 总耗时；
  - 用既有本地插桩证明器（`sapling_tx_construction` 同款）补充 Spend / Output 分段基线对照，
    并在报告中明确该分段来自对照基线、非 Zallet 实测。
- 所有计时报告须标注线程数 / 亲和性 / 主机（与既有实验保持一致的可复现字段）。

## 7. 内存方案（冻结）

- 采样：钱包进程与节点进程各自 RSS / 工作集，采样间隔 ≤ 1 s；二者同时运行时额外记录合并占用。
- 独立保留：首次同步峰值（一次性）、证明生成期间峰值。
- 记录 Zallet 历史扫描 batch size（已知显著影响内存）。

## 8. 一次性成本处理（冻结）

- 初次同步、测试资金（faucet）准备单独成表，不与每笔发送成本混算。
- 报告中位数交易成本时仅基于重复测量的 N 笔，不含一次性成本。

## 9. 资源上限与停止条件

- 资源上限：本实验为测量，不修改证明器；内存上限以环境可用内存为界，记录峰值但不设优化门槛。
- 停止条件：
  - 功能验证门禁失败且无法在合理时间内解决 → 回报限制，实验中止（负结果同样记录）。
  - 若测量显示端到端瓶颈完全在确认等待（网络），则结论明确为「证明非瓶颈」，不强行外推到证明优化收益。

## 10. 安全 / 侧信道说明

- 本实验**不修改**证明器，不引入新密码学实现；Zallet 的 `pczt_prove` 走其自带证明路径。
- 若后续要把本实验的分段计时用于论证「替换证明器」的收益，须回到 MSM Phase D 的预注册
  并补全侧信道语义评估（blst 点加非 constant-time，性能结果不等于可安全采用的生产实现）。
