> 本文件按 `sapling_optimization_validation_protocol_20261017.md` §5 的模板，**在动任何算法代码之前**填写并冻结。
> 一旦冻结，验收阈值与判定规则**不得修改**；实现与测量中若发现标准写错，只能在结果文档里标注，不能在本文档里改。

---

## 0. 一句话

目标 b 的候选机制选定为 **Pippenger 窗口的有符号（balanced）数字重编码**：用 20 个 13 bit 窗口替代 22 个 12 bit 窗口，在**保持桶数组几乎不变（4096 vs 4095）**的前提下把 fill 与 reduce 的群加次数同时降 **≈9%**。

---

## 1. 目标与选定机制

| 项 | 内容 |
|---|---|
| 目标 | **b：H query G1 MSM 时间**（报告 §5/§9 的时间主因） |
| 机制 | 有符号窗口重编码（balanced / BOS–Coster 型），窗口宽度 c=13，桶数 2^(c−1)=4096，chunk 数 20 |
| 不选其它机制的理由 | 见 §2（实测排除了内存、构建开关、纯 c 调参三类候选） |

**为什么这是"算法级"**：它改变了指数的**数字表示**与桶数组的**大小**，而不只是配置。根号下的群加次数下降，是本目标唯一有 >5% 空间的杠杆。

---

## 2. 证据基础（本次动手前已实测，非推断）

### 2.1 MSM 内部：fill 绝对主因（同一会话、1 线程、插桩）

来源：`experiments/raw/logs/sapling_exponent_density_census_20261017.stderr.log`（`SAPLING_MSM_STAGE_TIMING`）。

| 调用 | n | c | chunk | wall 中位 | fill | reduce | prep |
|---|---:|---:|---:|---:|---:|---:|---:|
| **h_query (G1)** | 131,071 | 12 | 22 | **1650.3** | **1547.9** | 101.6 | 43.7 |
| l_query (G1) | 98,638 | 12 | 22 | 484.0 | 375.5 | 103.5 | 11.1 |
| a_aux (G1) | 98,638 | 12 | 22 | 334.4 | 229.6 | 104.3 | 9.9 |
| b_g1_aux (G1) | 98,638 | 12 | 22 | 243.1 | 140.0 | 100.7 | 10.1 |
| b_g2_aux (G2) | 98,638 | 12 | 22 | 679.0 | 374.8 | 298.7 | 9.6 |
| 3 个小调用 | 8 | 3 | 85 | 3.7 | 0.2 | 3.4 | 0.0 |
| **合计** | | | | **3394.7** | 2668.2 | 712.3 | 84.5 |

单位 ms。**MSM 合计 = 3394.7 ms，占冻结单线程 prove 3685.6 ms 的 92%**；其中 H query 一项占全部 MSM 时间的 48.6%。

### 2.2 单次群加的成本是纯算术（本次微基准实测）

新增 `experiments/prover-smoke/src/bin/msm_window_bench.rs`（n=131,071，1 线程 @LP0）：

| 探针 | ns/次群加 |
|---|---:|
| `add_single_acc`（单累加器，纯依赖链） | 470 |
| `add_rand_bucket` c=8（36 KB 桶数组，L1 常驻） | 468 |
| `add_rand_bucket` c=10（147 KB） | 467 |
| `add_rand_bucket` c=12（590 KB） | 478 |

**桶数组大小对每次加法的成本没有影响**（36 KB vs 590 KB 差 <3%），所以 **fill 不是访存受限，而是算术受限**。bls12_381 的混合加（RCB2015 Alg.8）= 11 次 `Fp` 乘；11 × ~43 ns ≈ 470 ns，与实测吻合。

### 2.3 构建开关不是原因（已排除）

同一微基准、独立 `CARGO_TARGET_DIR`、四种构建：

| 变体 | ns/次群加 | MSM c=12 (ms) |
|---|---:|---:|
| 默认（`lto=false`, `codegen-units=16`, 通用 x86-64） | 470 | 1554.3 |
| `-C target-cpu=native` | 455 | 1521.4 |
| `lto=fat`, `codegen-units=1` | 465 | 1545.6 |
| 两者同时 | 441 | 1512.4 |

最好也只有 **−2.7%**，且组间差在噪声量级。**结论：无 LTO / 通用指令集不是 470 ns 的原因**，纯 Rust 可移植 6-limb Montgomery 就是这个成本。

### 2.4 纯窗口调参的空间太小（已算清）

总群加次数 = `⌈255/c⌉ × (n + 2·桶数)`。对 n=131,071：

| 方案 | chunk | 桶数 | 总群加 | 相对 now |
|---|---:|---:|---:|---:|
| now：无符号 c=12 | 22 | 4,095 | 3,063,742 | — |
| 无符号 c=13 | 20 | 8,191 | 2,949,060 | **−3.7%** |
| 无符号 c=14 | 19 | 16,383 | 3,112,903 | +1.6% |
| **有符号 c=12** | 22 | 2,048 | 2,973,674 | −2.9% |
| **有符号 c=13** | 20 | 4,096 | **2,785,260** | **−9.1%** |
| 有符号 c=14 | 19 | 8,192 | 2,801,645 | −8.6% |

**纯调 c 最多 −3.7%；有符号数字把桶数减半，才能在桶数组不变的前提下多拿 1 bit/窗口 → −9.1%。**

### 2.5 预期端到端效果

fill 与 reduce 都随 chunk 数等比缩放（20/22 = 0.909），prep 基本不变：

```
预期 MSM 时间 ≈ 2668.2×0.909 + 712.3×0.909 + 84.5 = 2425.4 + 647.5 + 84.5 = 3157.4 ms
相对 now 的 3394.7 ms = −7.0%   →  端到端 −7.0% × 92% ≈ −6.4%
```

**预测区间：端到端 −5% ~ −8%（1 线程）。** 这高于 §3 的 3% 阈值，因此本目标**有资格**被判定为"通过"；但预测本身不是结论。

## 4. 预声明验收标准（冻结）

| 字段 | 内容 |
|---|---|
| 目标 | b（H query G1 MSM 时间） |
| 改动文件 | `vendor/bellman/src/multiexp.rs`、`experiments/prover-smoke/src/bin/msm_window_bench.rs` |
| 假设 | 把 12-bit 无符号窗口换成 13-bit 有符号窗口，桶数几乎不变而 chunk 数 22→20，使 fill 与 reduce 的群加次数同时下降 ~9%；由于单次群加是纯算术成本（§2.2），次数下降应近似线性转化为时间下降 |
| **主验收指标** | **Spend 端到端 1t @ 掩码 `0x1` 暖态中位，相对同日/同二进制的 before 下降 ≥ 3%**（ABBA 配对，开关 off=A、on=B） |
| 辅助指标 1 | `SAPLING_MSM_STAGE_TIMING` 的 H query `bucket_fill_sum_ms` 与 `bucket_reduce_sum_ms` 中位下降 |
| 辅助指标 2 | 8t @ `0xFFFF` 端到端中位不退化（>1%） |
| 辅助指标 3 | Output 电路端到端中位不退化（>1%） |
| 内存指标 | `prove_peak_abs_bytes`（`prove_memory_ledger`，n≥3）**不得上升**；预期下降（H 窗口缓冲 22→20 槽，−2.1 MB） |
| 正确性 | ① 每批 5/5 `verified=true` 且 `proof_bytes=192`；② 微基准里**有符号与无符号两种模式的 MSM 结果逐位相同**（131,071 项整规模）；③ 64 项前缀与朴素 double-and-add 结果相同；④ 参数哈希与电路规模不变 |
| 回退条件 | 任一正确性项失败 → 立即回退该改动；主指标 <3% 且辅助指标无改善 → 记为"局部改动、未转化为端到端"并归档（不改默认值） |
| 预期样本量 | A/B 各 ≥3 批 × 5 次证明，ABBA 交错 ≥5 对；另跑 MSM 阶段计时批次 |
| 预声明日期 | 2026-10-17 |
| 冻结时 before 二进制 | `spend_prover_smoke.exe` SHA-256 `e5cedd7b9ac3c37a887d945faef9945b3f4830b96a6dcafec33d4b10cb7c72f0` |
| 本预注册的提交 | 本文件单独一个提交（先于任何代码改动）；提交哈希记录在结果文档里（自引用哈希无法写在自身内） |

**通过判据**：主指标达标 **且** 辅助指标无 >1% 退化 **且** 正确性全过。
**不通过但有效**：主指标未达标但辅助指标显著改善 → 记为"局部改善未转化"，归档。

## 5. 测量协议（沿用冻结协议 §3，额外声明）

1. 主口径：1 线程 @ `0x1`，≥3 批 × 5 次，弃第 1 批与每次 run 1。
2. A/B 在**同一二进制**内用 `SAPLING_MSM_SIGNED_DIGITS=0/1` 切换，ABBA 交错，避免重建与跨日混杂。
3. `SAPLING_PROFILE=0`；需要阶段口径时另跑（会拖慢，不计时）。
4. 机器状态：测量期间不跑其它负载；记录每轮空闲 CPU。
5. 正确性：微基准断言 + 每批 `verified` 检查（见 §4）。

## 7. 明确不做的（边界）

- 不实现 wNAF：MSM 需要对每个基点做多倍数预计算（131,071 × 2^(w−1) 个点），内存不可接受；有符号窗口是 MSM 场景下 wNAF 的对应物。
- 不改底层 `Fp` 算术（纯 Rust 可移植实现，改它属于换库/写汇编，超出本轮范围；且 §2.3 已证明构建开关只值 2%）。
- 不改变指数的**物化**方式（那是目标 a 的内存口径，本轮只动时间；物化缓冲会顺带缩小 9%，但不作为本目标的验收项）。
