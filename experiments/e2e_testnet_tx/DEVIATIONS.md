## 0. 预注册缺失（先说最要紧的一条）

原计划要求"测量前冻结预注册"，`README_runbook.md` 第 5 行链向
`../metadata/sapling_e2e_testnet_tx_preregistration_20261026.md`。

**该文件从未创建。** 全仓库检索确认不存在，也没有对应的历史提交。实际流程是：
10-26 写了范围界定文档与 runbook → 10-29 直接开始测量 → 事后才做模型比较。

**后果（必须如实承认）：**

| 分析动作 | 性质 | 说明 |
|---|---|---|
| 把 `spends` 与 `outputs` 分别计数 | **确认性** | 由交易结构决定，看数据前就唯一合理 |
| ZIP 317 手续费 `5000×max(S,O)` 校验 | **确认性** | 独立于数据的协议规则，可用作交叉验证 |
| `tx_size` 线性于 (S, O) | **确认性** | 结构必然 |
| **M1/M2/M3 三模型里选 M3** | **探索性** | 是在看到 out9 判别点后才确定；严格说应先冻结再选 |
| **output 边际 = 91.5 ms** | **探索性** | 同上，且区间宽（[90, 146]） |
| 剔除 `(4,3)` 离群点 | **探索性** | 事后判断 |

结论强度因此需要打折的地方只有一处：**"output 边际的具体数值"不能当作预注册的确认结果**，
它是在模型选择过程中产生的估计。而"spend 与 output 不同价""output 有成本""成本非线性于证明个数"
这三条不受影响——它们由等量替换对照（`S=3,O=3` vs `S=4,O=2`，同为 6 个证明但差 548 ms）
这类无模型证据支持，不依赖模型选择。

## 1. 偏离清单

### D1 · 测量环境：Testnet → WSL2 离线 Regtest

| | 原方案 | 实际 |
|---|---|---|
| 环境 | Zcash Testnet，docker compose | WSL2 离线 regtest，原生进程 |
| 理由 | runbook §0 称"Regtest 资金到账后缺少受支持的完整花费路径" | 该判断在 z3 的 beta.3 上不成立：regtest 自转在 `z_sendmany` 路径下完全可用 |

**触发原因**：Testnet 同步需 2–12 小时且依赖 faucet 人工领取，而 regtest 可确定性复现、
可任意挖块、可快照回滚。

**影响**：❌ 绝对值不可外推到主网（无网络传播、无真实 mempool 竞争）；
✅ 但证明与签名是纯本地计算，与网络无关，因此 **spend/output 的相对成本比（6.45:1）可移植**。
报告 §6 已声明此边界。

### D2 · 交易构造路径：PCZT 四阶段 → `z_sendmany`

| | 原方案 | 实际 |
|---|---|---|
| 路径 | `pczt_create → pczt_prove → pczt_sign → pczt_extract` | 单次 `z_sendmany` 异步提交 + 轮询 opid |
| 理由 | 原方案以 PCZT 为唯一被测对象 | **PCZT 的 Sapling 分支在 beta.3 上不可用**（见 `FAILURES.md` F2） |

**这是最大的偏离**，它改变了"测什么"：从「四个 RPC 阶段的分解」变成「一笔 Sapling 交易从提交到入块的墙钟」。
后者粒度更粗，但对成本建模更有用——因为它包含 build/prove/sign/broadcast 的真实串联。

**保留的补救**：PCZT 四阶段仍在 **Orchard/Ironwood** 路径上完整测到了（N=15，prove 占 95.1%），
见 `raw/pczt_pool_v2/REPORT_v2.md`。两条路径并列，没有假装其中一条是另一条。

### D3 · 池：Sapling → Orchard/Ironwood（仅 PCZT 部分）

PCZT 在 Sapling 上跑不通，于是 PCZT 的四阶段数据取自 Orchard/Ironwood 池。
代价是：**PCZT 的 prove 占比（95.1%）不能直接搬到 Sapling**，因为两者电路规模不同。
报告里两者分开陈述，未做混算。

### D4 · 样本口径：N≥5 笔「不同可花费 Note」→ 单账户自转

原方案要求 N≥5 笔不同 note（依赖 faucet 多次领取）。实际用同一账户反复自转
（每轮金额回到自己），spend 数通过金额放大到 1~17 个。

**影响**：✅ 形态（spends/outputs）覆盖更广（11 种形态 vs 原计划的单一形态）；
⚠️ 但 note 的年龄分布单一，未覆盖「从很旧的 note 花费」的情况。

### D5 · 统计口径：中位数 → 中位数 + 双变量回归 + 自助法

原方案只要求"每阶段中位数 + 波动范围"。实际做了回归建模与 B=4000 自助法 CI。
这是**增强而非削减**，但属于计划外分析，按探索性对待。

### 4.2 D6 · M7 结果不匹配标签与证据校验冲突（真实缺陷，会作废整 run）

**偏离性质**：不是计划外扩展，而是**实现与预注册不一致**的缺陷修复。

**事实**：M7 把 `form_mismatch` / `fee_mismatch` 写入主 CSV 的 `failure_class` 列；
而预注册第 32 行规定该二者**无 sidecar**、L214 规定其**不是失败类别**、§6-F 规定其
**不并入失败计数**。但 `verify_run_artifacts` 按「任何非空 `failure_class` 即失败轮」
要求其有 sidecar 记录 —— 二者直接冲突。

**后果链**：正式采集中出现**一次**形态/手续费不符 → 证据校验 `SystemExit` →
整个 run 被 `mark_run_aborted` 标为 `run_aborted` / `usable_as_sample=False` →
`fit_sapling_e2e_model.load_all` 据此**剔除该 run 的全部样本**。即：一次形态偏离
足以让整轮采集作废。

**为什么此前没被发现**：该路径需要「发送成功且回查形态/手续费不符」才会触发，
既有 29 轮试点数据与门禁 run 均未出现形态偏离，故从未被执行过；隔离 harness 在
本轮才首次覆盖该路径。

**修正**：证据校验时把这两个标签**排除**出「失败轮 ↔ sidecar」双向核对，并单独
计入 `meta.json` 的 `mismatch_rows`（**不计入** `failure_rows`，痕迹不丢失）。
**不改 M7 的分类、不改 tie-break、不改任何裁决行**；预注册补记「双重不匹配
tie-break：手续费优先」，并注明 `form_match` / `fee_match` 两列布尔值逐列保留于
`rounds.csv`，形态偏离信息不因 `failure_class` 单值化而丢失。
